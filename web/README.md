# Frontend «Аким на 5 часов»

React + TypeScript + Vite. Обзор районов, каталог 14 мероприятий, план из пяти решений, результаты Go, объяснение, локальная история и сравнение.

## Запуск с Go

Нужны Node.js **22.12+ (ветка 22) или 24+**, npm и Go 1.22+. Проверено на Node 24.20.0. Backend не изменён.

Терминал 1, корень репозитория:

```powershell
go run ./cmd/server
```

API слушает `http://localhost:8080`. Без `OPENAI_API_KEY` работает содержательное резервное объяснение. Ключ нужен только Go; никогда не добавляйте его в переменные `VITE_*`. При прямом `go run` файл `.env` автоматически не читается. Альтернатива: `docker compose up --build`.

Терминал 2:

```powershell
cd frontend
npm ci
npm run dev
```

На Windows при ограничении выполнения `npm.ps1` используйте `npm.cmd ci` / `npm.cmd run dev`. Откройте URL из вывода Vite: обычно `http://127.0.0.1:5173`; занятый порт меняется автоматически.

По умолчанию запросы идут на `/api`. Vite проксирует их в `http://localhost:8080`, CORS при этом не нужен. Это проверено реальным HTTP-запросом через Vite.

Для другого адреса скопируйте `.env.example` в `.env.local`:

```dotenv
VITE_API_BASE_URL=http://localhost:8081
VITE_MOCK_MODE=false
```

Перезапустите Vite. Для прямых запросов на другой origin запустите Go с `CORS_ORIGIN`, точно совпадающим с адресом frontend, например в PowerShell:

```powershell
$env:CORS_ORIGIN='http://127.0.0.1:5173'
$env:ADDR=':8081'
go run ./cmd/server
```

У `localhost` и `127.0.0.1` разные origin. Если Vite сменил порт, обновите CORS. В production отдавайте `dist` статическим сервером с proxy `/api` в Go или задайте `VITE_API_BASE_URL` **перед сборкой** и настройте CORS. Go сам frontend не раздаёт.

## Mock без backend

Включите `VITE_MOCK_MODE=true` либо кнопку «Режим разработки» в шапке. При ошибке загрузки доступна отдельная кнопка «Открыть mock без расчёта».

Жёлтая метка **MOCK** видна постоянно. `src/mock-scenario.json` — точный ответ текущего Go `GET /api/scenario`, включая названия всех 14 мероприятий, цены, лаги, эффекты, синергии и ограничения. Никакого автоматического переключения на mock при ошибке API нет.

В mock можно выбирать, редактировать и сохранять план. **Симуляция и AI отключены.** Фиксированного результата для произвольного выбора нет. JSON-ответы в `tests/fixtures` используются только в тестах и не входят в приложение.

## Как пользоваться

1. В обзоре изучите исходные показатели; значения строго ниже порога каталога отмечены `!` и цветом.
2. На экране «Ваши решения» выберите направление, мероприятие и район. Для городской меры район не отправляется даже как `null`.
3. Соберите ровно пять уникальных решений. Бюджет до 100, не больше двух мер направления. M1/M3 несовместимы глобально; M4/M7 и M5/M13 — только в одном районе. Источник правил — API.
4. В панели плана можно изменить район, заменить или удалить решение. Конфликтная смена района отклоняется с объяснением; предыдущее значение сохраняется. На компьютере слоты прокручиваются внутри закреплённой панели, бюджет и запуск остаются рядом. На узком экране есть закреплённая строка с количеством решений, бюджетом и переходом к плану.
5. «Рассчитать результат» доступна для валидного плана. Перед отправкой каталог запрашивается заново. При изменении каталога план остаётся на экране для повторной проверки.
6. `/api/simulate` возвращает расчёт; `/api/explain` загружается отдельно с тем же планом. Ошибка объяснения не удаляет расчёт. Повторная отправка во время расчёта блокируется.
7. В результате показаны Score до/после/разница, бюджет, все районы, все показатели, критические значения, эффекты мер и сработавшие синергии. Полный эффект из каталога отделён от эффекта с учётом лага из ответа Go. Последний показан до ограничения диапазоном; фактические изменения — в таблицах районов.
8. «Изменить решения» возвращает план. Любое изменение состава или района снимает текущий результат; старый остаётся в истории.

Объяснение API содержит только `source` и `text`. Текст выводится безопасной React-интерполяцией. `llm` обозначен как AI, `fallback` — как резервное объяснение без AI. Сильные стороны, риски, компромиссы и рекомендации показываются в той форме, в какой пришли от backend. Текущий fallback не содержит отдельного раздела рекомендаций, frontend его не придумывает.

## Черновик, история, версии

- Черновик: `localStorage['akim.draft.v1']`. Восстанавливается после загрузки и проверяется по актуальному API-каталогу. Устаревшие меры или районы сохраняются для явного исправления, запуск блокируется.
- История: `localStorage['akim.history.v1']`. Автоматически сохраняет успешный ответ Go, название, дату, решения, бюджет, объяснение при получении и полный снимок сценария.
- Повреждённый JSON или неполные записи не ломают приложение. При недоступном/переполненном хранилище появляется уведомление; текущая работа остаётся в памяти.
- Выберите два сценария флажками. Сравниваются значения Go: Score, бюджет, районные Score и показатели, критические хотя бы в одном состоянии. Новые Score не рассчитываются.
- API не отдаёт версию данных или движка. Сравниваются канонические снимки каталога, исходных показателей и правил. Разные снимки сопровождаются предупреждением; даже совпадение снимков не доказывает равенство версий Go.
- Удаление каждой записи подписано. Последнее удаление можно отменить в текущей сессии. Хранение только в этом origin/браузере, без облака, экспорта и синхронизации вкладок.

## Сборка и тесты

```powershell
npm test
npm run test:api
npm run test:integration
npm run build
```

`npm test` запускает Vitest + Testing Library в **jsdom**, без backend. Проверки валидации, хранения, ошибок API и взаимодействия с React.

`npm run test:api` требует живой Go на 8080: сверяет mock с API, проверяет пример 95, ограничения, все несовместимости, пары в разных районах, независимость порядка и параллельные запросы. Другой адрес: `$env:API_URL='http://localhost:8081'`.

`npm run test:integration` проходит реальное приложение в jsdom с HTTP-запросами к живому Go. Сервер запускайте **без ключа AI**, так как тест проверяет fallback. Проверяет выбор всех пяти мер, Score, сохранение ответа и восстановление черновика после повторного открытия. Это не визуальный браузерный тест.

`npm run build` запускает TypeScript и production-сборку Vite. `npm run preview` позволяет обслужить сборку локально; при развёртывании нужен отдельно настроенный proxy/API origin.

## Демонстрационный пример

M7 / Нура, M8 / Нура, M10 / Нура, M12 / весь город, M5 / Сарыарка.

Реально получено от Go при проверке: стоимость **95**, остаток **5**, `base_score=52.557680000000005`, `final_score=56.54306999999999`, `score_delta=3.985389999999988`, критические значения **2 → 0**. В интерфейсе итог округляется до **56,54**. Эти числа не подставляются в приложение.

## Устройство

- `src/main.tsx` — только запуск React.
- `src/App.tsx` — состояние плана, навигация, запросы и сохранение.
- `src/pages` — обзор, решения, результат, история.
- `src/components` — общая навигация, состояния, эффекты, оригинальный силуэт Астаны.
- `src/types.ts`, `api.ts`, `contract.ts` — типы, HTTP, проверка формы и соответствия ответа каталогу.
- `src/validation.ts` — ограничения выбора и бюджет; формулы Score здесь нет.
- `src/storage.ts` — безопасное чтение/запись localStorage.
- `src/style.css` — основа существующего оформления; `interface.css` — новые экраны, читаемость и адаптация.

## Реальные ограничения и непроверенные сценарии

Подробный отчёт: [DEMO-CHECK.md](DEMO-CHECK.md).

- Chrome и встроенный браузер недоступны в среде этой работы. Визуальная проверка реальных экранов **390, 768 и 1440 px не выполнена**, скриншоты не сняты. CSS адаптирован, но jsdom не проверяет геометрию, перекрытия, реальную видимость фокуса и touch.
- Tab/Enter и подписанные controls проверены в DOM. Видимость `:focus-visible`, системный `prefers-reduced-motion`, нативные select на телефоне, экранный диктор и Safari требуют ручной проверки.
- Живой платный LLM не вызывался. Реальный fallback без ключа проверен; ошибки провайдера покрыты существующими Go-тестами, сетевой сбой объяснения — frontend-тестами.
- Две HTTP-операции рассчитывают сценарий независимо. Если ответы различаются, объяснение не прикрепляется к старому расчёту. Версию движка API не сообщает.
- История локальна; пользователь может изменить localStorage вручную. Это не серверный журнал и не доказательство результата соревнования.
- Cross-origin production-развёртывание, реальное заполнение диска/localStorage, одновременное редактирование в нескольких вкладках и реальные мобильные устройства не проверены.

### Особенность Go из MSYS2 на этой машине

Если `go version` сообщает, что не найден GOROOT, для установленного здесь MSYS2 Go используется:

```powershell
$env:GOROOT='C:\msys64\ucrt64\lib\go'
go run ./cmd/server
```

У обычной установки Go этот шаг не требуется.
