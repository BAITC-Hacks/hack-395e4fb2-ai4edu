# Web «Аким на 5 часов»

React + TypeScript + Vite. Проект находится в `web/`, рабочая ветка — `feat/web`.
Контракт: [docs/api.md](../docs/api.md). Правила: [docs/scoring.md](../docs/scoring.md).
Backend-код frontend-веткой не меняется; оптимизатор и контракт получены из `origin/main`.

## Запуск

Нужны Go 1.22+, make, Node.js 22.12+ (ветка 22) или 24+ и npm. Проверено на Node 24.20.0.

Терминал 1, в корне репозитория:

```sh
make run
```

Терминал 2:

```sh
cd web
npm ci
npm run dev
```

Откройте URL из вывода Vite. По умолчанию это `http://127.0.0.1:5173`; занятый порт меняется автоматически.
В Windows при ограничении выполнения `npm.ps1` используйте `npm.cmd` вместо `npm`.
Без make можно выполнить `go run ./cmd/server`; в отличие от `make run`, эта команда не читает `.env` автоматически.
Если установленный через MSYS2 Go не находит GOROOT, в PowerShell задайте `$env:GOROOT='C:\msys64\ucrt64\lib\go'`.

Все запросы приложения идут по относительным путям `/api/scenario`, `/api/simulate`, `/api/explain`, `/api/recommend`.
`web/vite.config.ts` проксирует `/api` на Go в разработке. CORS для этого не нужен.
Адрес Go находится только в конфигурации proxy; переменной `VITE_API_BASE_URL` нет.

```sh
npm run build
```

Команда проверяет TypeScript и создаёт `web/dist`. Для production раздайте `dist` и проксируйте `/api` в Go на том же origin.
Go самостоятельно статические файлы frontend не раздаёт. `node_modules/`, `dist/`, `*.tsbuildinfo` и `.env.local` исключены через `web/.gitignore`.

## Каталог и план

- Обзор районов загружается из `GET /api/scenario`, включая все 14 мероприятий, их точные названия, стоимость, лаги и эффекты.
- Каталог фильтруется по пяти направлениям. Район выбирается явно; у городских M2, M6, M12, M14 поле `district_id` в запросе полностью отсутствует.
- Панель содержит пять слотов, замену/удаление решения, смену района и серверный бюджет.
- Локальные правила каталога дают быстрые подсказки у действий: ровно пять уникальных мер, бюджет до 100, не больше двух мер направления, несовместимости M1/M3 глобально и M4/M7, M5/M13 в одном районе.
- **Общая стоимость, остаток и подтверждённая валидность отображаются только из ответа Go.** После изменения черновика с задержкой 250 мс отправляется `/api/simulate`. Неполный набор получает штатный 422 с бюджетом и `validation_errors`; полный допустимый — 200. Score этой фоновой проверки не показывается и в историю не сохраняется.
- Во время проверки/ошибки прежние бюджет и валидность скрываются. Устаревшие запросы отменяются. Кнопка запуска ждёт подтверждения Go. Ошибка позволяет повторить проверку, не теряя план.
- При запуске каталог проверяется заново. Изменившийся каталог требует повторного просмотра плана.

## Интерактивная схема районов

В обзоре и результате доступна **«Условная визуализация · синтетические данные»**: единая изометрическая городская сцена с объёмными зданиями, рекой, мостами, улицами и зелёными пространствами. Это авторская иллюстрация, а не официальные границы, площади, соседство районов или адреса работ. Зависимостей для карт и 3D-движка нет.

- `src/components/districtGeometry.ts` содержит только геометрию и связь с ID районов. `CityScene.tsx` содержит фиксированную композицию архитектуры. Значения и названия поступают из API через `DistrictVisualization.tsx`. Проверенные геоданные впоследствии можно подключить отдельным геометрическим адаптером.
- Выбор района нажатием, Enter/Пробел или стрелками открывает детали и синхронизируется с существующей таблицей. Таблица остаётся альтернативой схеме. Home/End выбирают первый/последний район в порядке таблицы.
- Селектор содержит отдельные показатели `indicator_order` / `indicator_names`. Цветовая шкала 0–100 одинакова для всех районов и для «До»/«После». Средние по категориям не рассчитываются.
- В результате используются `district_before_after[].before/after` и непосредственно `indicator_deltas`. Режим «Изменение» различает снижение, ноль и рост цветом, знаком и подписью легенды. Критическая отметка `!` в этом режиме относится к **итоговому показателю**, а не к дельте. Значение ровно на пороге не критическое.
- Цвет показателя относится к участкам земли; здания сохраняют общую зелёную палитру. Компактные подписи содержат название, значение, `!` и число районных мер в скобках; в деталях выбранного района — метки ID и названия мер. Городские меры вынесены отдельно как действующие на все районы. Метки не указывают строительные площадки. В архивном результате они всегда соответствуют его `result.decisions`.
- «Показать подходящие меры» открывает каталог с ненулевым полным эффектом на выбранный показатель, включая отрицательный эффект и городские меры. Район предварительно выбран в карточках; решение добавляется только явной кнопкой. Фильтр можно снять. Даже переход из истории не заменяет текущий черновик архивным планом.
- После изменения плана старый текущий результат и его схема скрываются, а сохранённый расчёт остаётся в истории.

На узких экранах вместо уменьшенных SVG-подписей доступны отдельные HTML-кнопки районов с читаемыми числами и критическими отметками; детали находятся под сценой. Предусмотрены клавиатурный выбор, видимый фокус и reduced motion. Фактическая отрисовка пока не проверена из-за недоступности браузера.

### Появление города

При первом появлении сцены в области просмотра она собирается примерно за **6,6 секунды**: основания → каркасы → фасады и крыши → окна и озеленение. Последовательность иллюстративна и не представляет расписание работ. Число зданий, их высота и расположение заранее нарисованы и не выводятся из показателей, мер или Score.

Над сценой есть **«Пауза анимации»**, **«Продолжить анимацию»** и **«Повторить анимацию»**. Пауза оставляет выбор районов, показателей и режимов результата рабочим. Повтор запускает только декоративную последовательность; план и результат не меняются. Смена показателя/района/режима, фоновое объяснение и другие повторные рендеры не перезапускают город. В браузерах без IntersectionObserver запуск происходит при открытии страницы.

При `prefers-reduced-motion` отображается завершённый статичный город, управление движением отключено. Если настройка включена во время просмотра, последовательность останавливается. После её отключения движение возобновляется только явным повтором. Декоративный силуэт Астаны в шапке статичен: отдельной фоновой анимации нет.

На результате тонкие золотые акценты обозначают районы, затронутые выбранными мерами расчёта. Городская мера затрагивает все пять районов. Это условные акценты, не местоположение построек и не количественный прогноз; источником служит `result.decisions`, а не редактируемый черновик.

## Результат и объяснение

Явный запуск отправляет `/api/simulate`, сохраняет Result и затем отдельно запрашивает `/api/explain` с тем же планом.
Повторный запуск во время запроса блокируется. Ошибка сохраняет решения; ошибка explain сохраняет уже доступный расчёт.

Score, его разница, стоимость, итоговые значения всех районов, фактические дельты, реализованные эффекты и синергии берутся из ответа Go.
Полный эффект каталога отделён от реализованного эффекта `applied_effects`, который дан до clipping. Фактические изменения берутся из `indicator_deltas`.
Формула Score во frontend отсутствует.

Оценки пяти районов и выбранный показатель представлены полосами «до / после» с общей шкалой 0–100 и числовыми подписями. Показатель переключается над графиком. Рост, снижение и критические значения обозначаются словами и знаками, а не только цветом. Порог берётся из сценария; равное порогу значение не считается критическим. Городской Score показан отдельно, без ограничения шкалой 0–100. Подробные таблицы всех показателей сохранены.

При 422 используются `validation_errors`; русский текст выбирается по `code`, а не английскому `message`. Связанные `measure_ids` сохраняются.
`explanation.text` выводится React как обычный текст. HTML не интерпретируется.
`source=llm` обозначен как «Объяснение ИИ», `fallback` — как «Резервное объяснение · без ИИ».
Отдельных полей рекомендаций в `/api/explain` нет. Frontend не дописывает отсутствующие разделы.

Изменение решений скрывает предыдущий текущий результат, сохраняя его в истории.
Если `/api/explain` вернёт другой Result, его текст не прикрепляется к старому расчёту.

## Рекомендация оптимизатора

На экране решений есть «Показать лучший план»: `POST /api/recommend` с телом `{"mode":"best"}` **без поля decisions**.

- При `503` и `validation_errors[].code=not_ready` показывается **«Считается…»**, запрос повторяется через две секунды.
- Первые примерно 15 секунд после старта Go — лишь ориентир; ожидание продолжается до готовности, его можно отменить.
- Смена страницы отменяет запрос и повторения. Другие ошибки 503 не повторяются автоматически; показывается ошибка и ручной повтор.
- Score, стоимость, остаток, критические значения и пять решений рекомендации берутся из `best`.
- Кнопка «Заменить текущий план рекомендацией» явно заменяет все пять решений. Полный результат и AI загружаются обычным запуском.

Кнопка **«Улучшить мой план»** отправляет `POST /api/recommend` с `{"mode":"improve","decisions":[...]}`. Она доступна только для полного плана после успешной серверной проверки.

- Сервер возвращает `current_score` и до трёх вариантов одной замены: мероприятия либо района. Остальные четыре решения сохраняются.
- Для каждого варианта показаны заменяемое решение и предложение, Score, прирост относительно текущего плана, потраченный/оставшийся бюджет и критические значения. Прирост используется из `score_delta`, а не вычисляется во frontend. Текущие бюджет и критические значения — из последней проверки `/api/simulate`.
- Пустой список означает отсутствие улучшения **одной заменой**, а не доказательство глобального оптимума.
- Применение требует отдельного нажатия «Применить вариант …». Предыдущий план можно вернуть кнопкой «Отменить применение рекомендации»; отмена доступна в текущей сессии, включая переходы между страницами, до следующего изменения решений или перезагрузки. Это работает и для рекомендации `best`.
- Применение и отмена запускают новую проверку плана, сохраняют черновик и скрывают предыдущий текущий результат. Сохранённая история остаётся доступной.
- Повторный запрос во время поиска блокируется. Поиск можно отменить; изменение решений/района, режима или уход со страницы отменяют запрос. Запоздавший ответ не показывает варианты от прежнего плана, даже при быстром изменении A → B → A.
- Ошибки отображаются по `validation_errors[].code`, с ручным повтором. `improve` не опрашивается автоматически при 503.

Обе рекомендации — результат оптимизатора Go, а не ИИ. Они не подменяют объяснение `/api/explain`.

## Mock без backend

Скопируйте `.env.example` в `.env.local` и задайте `VITE_MOCK_MODE=true`, либо нажмите «Перейти в учебный режим» в шапке.
При ошибке каталога есть отдельная кнопка «Открыть учебный режим (mock)». Автоматического переключения нет.

Постоянная метка **«Учебный режим (mock) — без расчёта»** объясняет ограничение. `src/mock-scenario.json` — снимок реального `/api/scenario`, сверяемый тестом с Go.
Можно собирать и сохранять план. Общая стоимость и валидность не подтверждаются; симуляция, объяснение и оптимизатор отключены.
Фиксированного ответа для произвольного сценария нет. Файлы `tests/fixtures` не входят в приложение.

## Сохранение и сравнение

Черновик в `akim.draft.v1` восстанавливается из localStorage и проверяется по актуальному каталогу и сервером.
Повреждённые данные не ломают приложение; устаревшие меры/районы можно явно исправить.

Успешные запуски сохраняются в `akim.history.v1`: название, дата, план, полный ответ Go, объяснение и снимок исходного каталога.
Два результата сравниваются по серверным Score, районам и критическим показателям. Новые Score не рассчитываются.
Разные снимки данных сопровождаются предупреждением о несопоставимости. Даже одинаковые снимки не подтверждают одинаковую версию движка: API её не передаёт.
Удаление каждой записи подписано, последнее удаление можно отменить в текущей сессии.
История локальна для текущего браузера/origin; нет облака и синхронизации вкладок. Ошибка/квота localStorage показывается пользователю.

## Проверки

```sh
npm test
npm run test:api
npm run test:integration
npm run build
```

- `npm test`: Vitest + Testing Library в jsdom, без сервера. Валидация, хранение, API, выбор решений, клавиатура в DOM, серверный бюджет, `503 not_ready → 200`, графики/строгий порог, применение/отмена улучшения, пустые ответы, ошибки и запоздавшие ответы при редактировании/навигации.
- `npm run test:api`: нужен живой Go. Проверяет каталог, документированный пример, ограничения, все несовместимости, параллельные запросы, лучший план и каждый вариант улучшения, сверяя их с `/api/simulate`. Проверяет также пустой список improve и 422. Ожидание best ограничено 120 секундами в тесте.
- `npm run test:integration`: реальное React-приложение в jsdom с HTTP-запросами в Go. Сервер запускайте без AI-ключа: тест проверяет fallback, выбор пяти мер, серверный бюджет, результат, улучшение, явное применение, отмену, скрытие старого результата и восстановление черновика после повторного открытия.
- Для HTTP-тестов другой адрес задаётся через `API_URL`; это настройка тестового процесса, не приложения.

Документированный план: M7/Нура, M8/Нура, M10/Нура, M12/город, M5/Сарыарка.
Реальный Go ответ: стоимость **95**, остаток **5**, Score после **56.54306999999999**, отображение **56,54**, критические значения **2 → 0**.
Оптимизатор при проверке вернул стоимость **98**, Score **57.236734999999996**. Числа не подставляются в приложение.

## Ограничения проверки

[Отчёт перед демонстрацией](DEMO-CHECK.md). Браузер недоступен: реальные экраны 390/768/1440 px, видимость фокуса, системный reduced motion и touch пока визуально не проверены.
Клавиатурный путь проверен в DOM; это не замена браузеру. Живой LLM с ключом не вызывался; настоящий fallback проверен.
Production reverse proxy, реальные мобильные устройства, quota браузера и многовкладочная синхронизация не проверены.
Все данные синтетические; оригинальная иллюстрация Астаны не является картой районов. Таймера, событий и декоративных графиков нет.
