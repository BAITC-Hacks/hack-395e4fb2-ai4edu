# Проверка перед демонстрацией HackAlem

Дата: 23 сентября 2026. Активный frontend: `web/`, ветка `feat/web`.
Этот отчёт описывает проверки, повторно выполненные после текущих изменений. Backend, корневые README/Makefile/Dockerfile не менялись. Коммиты и push не выполнялись.

Сохранены зелёная навигация, светлая рабочая область, оригинальный силуэт Астаны, каталог, черновик, история и сравнение. Иллюстрация не является картой районов. Новых зависимостей и формулы Score во frontend нет.

Оценки районов и показатели имеют общую шкалу 0–100 согласно docs/scoring.md. Городской Score показан отдельно без такой шкалы. Критическим считается значение строго ниже порога сценария; равное порогу не помечается критическим. Подробные таблицы и раскрываемые сведения об эффектах сохранены.

### Особенности схемы

- Геометрия вынесена в `districtGeometry.ts`: нет значений показателей, официальных границ, строительных адресов или предположений о соседстве районов. Видимая подпись: **«Условная схема районов · синтетические данные»**.
- Фигуры обозначают ровно пять районов из сценария. Если ID переименован, он получает свободную условную фигуру, без наложения на известный район.
- Обзор показывает исходные данные и метки текущего черновика. Результат показывает показатели и меры конкретного ответа сервера, включая архивные записи.
- Имена и числа видны непосредственно на фигурах; `!` добавляет нецветовой признак критического состояния. Метки ID мер перечислены в деталях района, городские меры — в отдельном блоке. На фигуре указано число районных мер.
- «До» и «После» используют одну шкалу 0–100; знак изменения и легенда различают снижение, ноль и рост. В режиме «Изменение» критическая отметка проверяет значение **после** решений, а не дельту.
- Кнопка подходящих мер только фильтрует каталог и предварительно выбирает район. Переход из истории не заменяет текущий черновик. Схема старого текущего расчёта исчезает после изменения плана.
- `ImprovePlan` и `ResultCharts` сохранены без изменений. Новых зависимостей и изменений backend нет.

### Что покрывают тесты

- Ровно пять решений, бюджет, повторы, третья мера направления; M1/M3 глобально, M4/M7 и M5/M13 в одном районе и допустимость разных районов.
- Выбор/смена района с конфликтом, замена/удаление меры, фильтры, отсутствие `district_id` у городских мер.
- Проверка стоимости сервером, ошибки 422/500, не-JSON ответ, недоступная сеть, таймаут, повторная отправка, сохранение плана при ошибке.
- Безопасный текст ИИ, fallback, сохранение результата при ошибке объяснения и отказ смешивать несовпадающие расчёты.
- Черновик и история, повреждённые данные, ошибка записи, сравнение разных снимков, удаление и восстановление записи.
- Графики по серверным значениям, переключение показателя, строгий/изменённый порог, обозначения роста/снижения/равенства; городской отрицательный Score не обрезается.
- Improve доступен только после подтверждения полного плана; проверяются загрузка, запрет двойного запроса, пустой ответ, ручной повтор, 422 и 503 без автоматического опроса.
- Рекомендация не применяется без действия; показ замены только района, применение и отмена, повторная проверка, сохранение черновика и истории, скрытие старого результата.
- Снятие устаревших предложений при редактировании; отмена при уходе; поздние ответы после отмены и быстрых A → B → A не восстанавливают старые варианты.
- Tab/Enter для навигации и выбора решения; Tab/Enter/Space для поиска и применения улучшения в DOM. Это не проверка реальной отрисовки фокуса.
- `best`: управляемые ответы `503 not_ready → 200`, отмена и уход со страницы. Живой сервер уже завершил поиск: стартовый 503 в этом проходе не наблюдался.
- Схема: ровно пять районов, смена показателя из API, клик/Enter/Пробел/стрелки/Home/End, выбор в обе стороны со схемы и из таблицы.
- Общая цветовая шкала до/после; дельта берётся из `indicator_deltas` даже в тесте с намеренно отличающимся after−before. Порог 40/39,99, изменение порога, критичность конечного значения при положительной дельте.
- Разделение районных и городских мер, метки архивного результата, явный переход с сохранением решений/названия текущего черновика и скрытие старой схемы после изменения плана.

Числа fixtures используются только в тестах. Успешные живые HTTP-проверки не используют подмены серверных ответов. Ошибки сети и редкие гонки воспроизводятся управляемыми ответами тестов.

- [ ] **1440 px:** две колонки каталога и панель решений читаются; бюджет и запуск доступны при прокрутке панели.
- [ ] **Схема на всех трёх ширинах:** имена/числа/критические отметки читаются; на телефоне детали расположены ниже, ничего не перекрывается; фокус фигуры и легенда видны; данные можно прочитать через таблицу.
- [ ] Реальные Tab / Shift+Tab / Enter / Space / стрелки; видимость фокуса, возврат к отмене после применения и к плану после отмены.
- [ ] Системный reduced motion: CSS отключает анимации и переходы, но фактическая отрисовка не проверена.
- [ ] Touch, экранная клавиатура, Safari, масштаб текста 200%, экранный диктор.

## Как пройти вручную

1. В корне запустите `make run`, в `web/` — `npm run dev`; откройте адрес Vite.
2. В «Ваши решения» выберите M7/Нура, M8/Нура, M10/Нура, M12/город, M5/Сарыарка. Дождитесь подтверждения: 95 потрачено, 5 осталось.
3. Нажмите «Рассчитать результат»: ожидается 56,54 из Go. Переключите показатель в «Где меняется жизнь», проверьте таблицу Нуры и отметку источника объяснения.
4. Вернитесь через «Изменить решения», нажмите «Улучшить мой план». До применения пять решений должны оставаться прежними.
5. Примените вариант, дождитесь новой проверки. На странице результата должен быть запрос нового расчёта; старый расчёт доступен в истории.
6. Вернитесь к решениям и отмените применение. Должны восстановиться исходные пять решений, стоимость 95 и остаток 5 после проверки.
7. Во время поиска измените район или уйдите на обзор: старый ответ не должен появиться при возврате. Проверьте учебный режим — расчёт и рекомендации недоступны.
8. Повторите просмотр всех четырёх страниц на 390/768/1440 px и управление только клавиатурой.
9. На обзоре выберите район на схеме и затем другой в таблице: выделение должно совпадать. Смените показатель, откройте подходящие меры — план не должен измениться. На результате сравните режимы «До», «После», «Изменение» и проверьте легенду; для просмотра из истории метки должны относиться к архивному расчёту.

## Реальные ограничения

- Пустой improve говорит только об отсутствии улучшений одной заменой.
- Undo рекомендации хранится в памяти текущей сессии, до ручного изменения решений или перезагрузки; применённый черновик сохраняется в localStorage. При следующей рекомендации отменяется только последняя замена.
- API не передаёт версию движка. Одинаковые исходные данные не доказывают полную сопоставимость расчётов разных версий; предупреждение сохранено.
- История локальна для браузера/origin, ограничена квотой; облака и согласования вкладок нет.
- Учебный режим (mock) позволяет редактировать каталоговый план, но не выполняет расчёт и не выдаёт фиксированный результат.
- Fallback содержит только текст, предоставленный сервером. Отсутствующие рекомендации не сочиняются.
