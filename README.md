# hack-395e4fb2-ai4edu
Hackathon team repository for AI4EDU

## «Аким на 5 часов»: backend

Детерминированный симулятор управления городом на Go, без внешних зависимостей.
Набор данных встроен в `internal/simulation/dataset.go`. Все числа рассчитываются
в Go; отдельный AI-слой объясняет готовый результат. Без API-ключа доступно
содержательное шаблонное объяснение. Спецификация и названия мер/показателей:
[docs/scoring.md](docs/scoring.md).

### Быстрый старт

```sh
cp .env.example .env        # при необходимости вписать OPENAI_API_KEY
docker compose up --build   # или: make up; API на http://localhost:8080
make demo                   # golden-сценарий → /api/simulate
make demo-explain           # тот же сценарий → /api/explain
```

Без Docker: `make run` (нужен Go 1.22+, `.env` подхватывается автоматически).
`make help` показывает все цели, `make check` запускает gofmt, vet, тесты и race.
Best (`POST /api/recommend`, `mode=best`) доступен через несколько секунд после старта; до готовности возвращается 503 `not_ready`, остальные запросы работают сразу.
В Docker контейнер всегда слушает 8080; внешний порт меняется через `HOST_PORT`.

### Архитектура

- `internal/simulation` — dataset, валидация и детерминированный расчёт `Result`.
  Движок не зависит от AI и не делает сетевых запросов.
- `internal/explanation` — интерфейс LLM-клиента, OpenAI Responses API и
  шаблонный fallback. Провайдер получает сериализованную копию результата,
  названия выбранных мер и показателей, направления, горизонт и критический порог.
  `Result` содержит дельты, синергии, эффекты мер и breakdown. Промпт запрещает
  пересчитывать числа, округлять их или называть числа вне входных данных.
- `internal/httpapi` — общий путь разбора запроса, валидации и расчёта для
  `/api/simulate` и `/api/explain`; middleware CORS обрабатывает OPTIONS до mux.
- `cmd/server` — настройка сервера и провайдера из переменных окружения.

Score всегда остаётся в `result`: ответ LLM может изменить только текст
объяснения. Это позволяет воспроизвести расчёт независимо от доступности AI.
Тесты используют фейковый клиент и HTTP transport без обращений к сети.

### Запуск и проверки

Требуется **Go 1.22 или новее**. Внешних Go-зависимостей нет.

```sh
go run ./cmd/server
# Другой адрес:
ADDR=:8081 go run ./cmd/server

go test ./...
go test -race ./...
go vet ./...

# Проверка совместимости; при первом запуске нужна сеть для загрузки тулчейна:
GOTOOLCHAIN=go1.22.12 go test ./...
```

### AI и переменные окружения

Пример настроек — [.env.example](.env.example). Сервер читает только переменные
окружения процесса и сам `.env` не читает; его подхватывают `make run`
и `docker compose`. При `go run` переменные нужно экспортировать вручную. Реальный ключ
не нужно записывать в репозиторий: `.env` и `.env.*` исключены через `.gitignore`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `ADDR` | `:8080` | Адрес HTTP-сервера |
| `OPENAI_API_KEY` | пусто | Ключ OpenAI, только на backend; без ключа используется fallback |
| `OPENAI_MODEL` | `gpt-4.1-mini` | Модель для объяснения |
| `CORS_ORIGIN` | пусто | Единственный разрешённый origin, например `http://localhost:5173` |

Клиент использует [OpenAI Responses API](https://developers.openai.com/api/docs/guides/text)
с `store=false`. Ключ отправляется только провайдеру в заголовке Authorization,
не включается в промпт, HTTP-ответы или логи. Таймаут LLM — 10 секунд без повторных
запросов; `WriteTimeout` сервера — 25 секунд, включая время чтения запроса.

Нет ключа, ошибка провайдера, таймаут, пустой/некорректный/незавершённый ответ
или отказ модели → HTTP 200 с исходным результатом и `source="fallback"`.
Fallback описывает крупнейшие улучшения и синергии, слабейший район, оставшиеся
критические значения и ухудшения, остаток бюджета и выбранные направления.
Его текст детерминирован и не выдаётся за ответ LLM.

При пустом `CORS_ORIGIN` заголовки `Access-Control-Allow-*` не выставляются.
`*` не поддерживается; разрешается только точное совпадение origin. OPTIONS
возвращает 204, но разрешающие заголовки получает только настроенный origin.
Разрешены GET/POST/OPTIONS и Content-Type, без credentials.

### API

Полный контракт для фронтенда и AI-участника, схемы и реальные примеры:
[docs/api.md](docs/api.md).

`GET /api/scenario` возвращает районы с исходными показателями, мероприятия,
их `name`, таблицы `indicator_names` и `category_names`, веса, бюджет, горизонт,
ограничения, синергии и параметры формулы Score.

`POST /api/simulate` принимает ровно 5 уникальных мероприятий стоимостью не
более 100. Максимум 2 мероприятия одной категории. Для локальной меры нужен
`district_id`; для городской поле нужно полностью исключить (даже `null`
не допускается).

Районы: `esil`, `almaty`, `saryarka`, `baikonur`, `nura`.

```sh
curl http://localhost:8080/api/scenario

curl http://localhost:8080/api/simulate \
  -H 'Content-Type: application/json' \
  -d '{"decisions":[
    {"measure_id":"M7","district_id":"nura"},
    {"measure_id":"M8","district_id":"nura"},
    {"measure_id":"M10","district_id":"nura"},
    {"measure_id":"M12"},
    {"measure_id":"M5","district_id":"saryarka"}
  ]}'
```

Для этого сценария: `total_cost=95`, `remaining_budget=5`,
`base_score=52.55768`, `final_score=56.54307`, `score_delta=3.98539`,
`critical_before=2`, `critical_after=0`. Числа в JSON передаются без округления.

Успешный ответ (HTTP 200) включает:

- `valid`, `total_cost`, `remaining_budget`, канонически отсортированные `decisions`;
- `base_score`, `final_score`, `score_delta`, `critical_before`, `critical_after`;
- `district_before_after`: показатели и районный Score до/после, долю населения;
- `indicator_deltas`: фактические изменения после clipping, по ID района и показателя;
- `applied_effects`: эффекты мер до clipping, целевой район и множитель лага;
- `applied_synergies`: применённые бонусы без лага, пары мер и целевой район;
- `base_breakdown`, `final_breakdown`: средневзвешенный районный Score,
  минимальный районный Score и штраф за критические показатели.

Ошибки сценария возвращают HTTP 422, `valid=false` и массив
`validation_errors` с `code`, `message`, а при необходимости `measure_ids`.
Поля Score отсутствуют. Стоимость невалидного сценария — сумма известных
мероприятий во входном списке (включая повторы); неизвестные ID не имеют цены.
Остаток бюджета при перерасходе отрицательный.

Некорректный JSON, неизвестные поля и несколько JSON-объектов в запросе
возвращают HTTP 400; тело больше 64 КиБ — HTTP 413. Эти ответы тоже содержат
`valid=false` и `validation_errors`, без Score.

Декодирование использует стандартный `encoding/json`: регистр имён полей
не учитывается, при повторе JSON-ключа действует последнее значение.
Строгая проверка этих двух случаев пока не добавлена.

### Объяснение сценария

`POST /api/explain` принимает тот же объект `{"decisions":[...]}`, что и
`/api/simulate`. Передавать собственные Score или готовый `Result` нельзя.
Успешный ответ имеет форму:

```text
{
  "result": <полный Result, идентичный ответу /api/simulate>,
  "explanation": {
    "source": "llm" или "fallback",
    "text": "Сильные стороны… Риски… Компромиссы…"
  }
}
```

У `explanation` только строковые поля `source` и `text`. Невалидный сценарий
возвращает HTTP 422 с тем же телом, что `/api/simulate`, без обёртки `result`,
объяснения и вызова LLM. Ошибки JSON и размера тела также совпадают.

На фронтенде выводить `explanation.text` как текст (`textContent` или обычная
интерполяция React/Vue), не через `innerHTML`/`dangerouslySetInnerHTML`/`v-html`.

### Расчёт

После валидации эффекты мер умножаются на `(8 - lag) / 8`. Городские эффекты
полностью применяются к каждому району, локальные — к выбранному району.
Затем добавляются синергии и все показатели ограничиваются диапазоном `[0, 100]`.
Районные Score — взвешенные суммы показателей. Городской Score:

```text
0.7 * sum(population_share[d] * district_score[d])
+ 0.3 * min(district_score[d])
- count(indicator[d][k] < 40)
```

Порядок решений не влияет на результат. Расчёты используют фиксированный
порядок суммирования; данные каждого запроса изолированы. LLM не участвует
в валидации и расчёте Score.

### Демо для жюри

1. Запустить `docker compose up --build` (или `make run`) без `OPENAI_API_KEY`. Для отдельного фронтенда
   задать `CORS_ORIGIN=http://localhost:5173`.
2. Вызвать `GET /api/scenario`: показать названия мероприятий, показатели,
   бюджет 100 и требование ровно 5 решений.
3. Отправить golden-запрос из примера в `/api/simulate`, затем тот же запрос
   в `/api/explain`: Score 56.54307, стоимость 95, критических значений 0;
   объяснение работает без сети с `source="fallback"`. Для демонстрации LLM
   перезапустить сервер с `OPENAI_API_KEY` в окружении и повторить `/api/explain`;
   при успешном ответе провайдера будет `source="llm"`, а `result` останется тем же.
4. Удалить одно решение: оба endpoint вернут 422 без Score; AI не вызывается.
