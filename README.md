# «Аким на 5 часов» — AI-симулятор управления городом

Проект автоматически готовит и сравнивает управленческие планы при ограниченном
бюджете. Пользователь описывает цель, например «подними итоговый Score Нуры,
устрани критические показатели, бюджет 100». Мастер-агент формализует цель,
планировщик получает варианты из точного поиска, рецензент проверяет цель и объяснение.
Ошибки понимания возвращаются мастеру, ошибки предложения — планировщику.
Go проверяет все числа и ограничения и формирует численное подтверждение оптимума.
Готовые пять мероприятий и **Astana Quality of Life Score** появляются в интерфейсе.
Ручной выбор решений и прежний AI-советник также доступны.

**Текущее состояние:** Go-backend, HTTP API, детерминированная модель,
точный оптимизатор, React frontend с историей, AI-автопилот с тремя OpenAI-ролями,
прежний советник, опциональная NVIDIA-рецензия и автоматические тесты.
Подробный контракт автопилота: [docs/autopilot.md](docs/autopilot.md).

**Данные синтетические.** Названия районов используются для понятного контекста;
числа и эффекты мероприятий не являются фактическими показателями или прогнозом
развития Астаны. Score — метрика этого симулятора, не официальный городской индекс.

## Быстрый запуск

Команды выполняются из корня репозитория, где находится `go.mod`.
Требуются **Go 1.22+** и, для команд `make`, GNU Make. Для примеров API нужен `curl`.
Для интерфейса нужен Node.js 22.22.2+ или 24.15+ и npm. Внешних Go-зависимостей, базы данных
и загрузки датасета нет.

### Локально

```bash
# Создать конфигурацию только если её ещё нет; существующий .env не изменяется.
if [ ! -f .env ]; then cp .env.example .env; fi

make run
```

Сервер по умолчанию доступен по адресу `http://localhost:8080`.
`make run` загружает переменные из `.env`. `make check` запускает проверки.
Поиск оптимума работает в фоне: `/api/recommend` с `mode=best` возвращает
503 `not_ready` до готовности; остальные запросы работают сразу.
Запуск без Make (переменные окружения загрузите самостоятельно):

```bash
go run ./cmd/server
```

При прямом `go run` файл `.env` не загружается: настройки должны быть экспортированы
в окружение процесса. Остановить локальный сервер можно через `Ctrl+C`.

В другом терминале:

```bash
curl -sS http://localhost:8080/api/scenario
make demo          # расчёт контрольного сценария, без AI
make demo-explain  # объяснение результата
make demo-advise   # предложения агента и независимая рецензия
```

Без ключей доступны расчёт и шаблонное объяснение. Для настоящих AI-вызовов
настройте провайдеров, как описано ниже. `demo-explain` и `demo-advise` при наличии
ключей расходуют API-квоту; тесты ключей не требуют.

### Интерфейс и автопилот

В отдельном терминале:

```bash
cd web
npm ci
npm run dev
```

Откройте адрес Vite и вкладку **AI-автопилот**. Нужен `OPENAI_API_KEY` в серверном
`.env`; NVIDIA для автопилота не требуется. Введите цель и запустите задачу.
Выбирать пять решений заранее не нужно. Завершённый план сохраняется в истории
браузера; незавершённый результат явно помечается. Подробности: [web/README.md](web/README.md).

По умолчанию: до трёх общих итераций, включая исправление цели мастером, три минуты на задачу,
два одновременных запуска, оценочный бюджет $0.10 на запуск и $50 суммарно
для автопилота. Лимит резервируется до API-запроса; локальный журнал
`.autopilot/usage.json` сохраняется между перезапусками и исключён из Git.
Эти суммы не являются балансом OpenAI и не включают вызовы других эндпоинтов.
Без возврата к мастеру допускается до семи API-вызовов; с исправлениями формальной
цели — до девяти. Повторная интерпретация не сбрасывает лимиты итераций, времени и расходов.

### Docker

Нужны Docker и Docker Compose с поддержкой `env_file.required` из `compose.yaml`.

```bash
docker compose up --build
# Либо фоновый запуск:
make up
# Остановить:
make down
```

Контейнер слушает порт 8080. `HOST_PORT` меняет внешний порт, например
`HOST_PORT=8081 docker compose up --build`. Тогда для демо используйте
`make PORT=8081 demo`. Файл `.env` подключается Compose, но не включается в образ.
Журнал бюджета автопилота находится в постоянном томе `autopilot-state`.
Удаление тома удаляет и накопленный локальный учёт расходов.

## Данные и правила

Источник данных — [internal/simulation/dataset.go](internal/simulation/dataset.go).
Полный каталог и формулы — [docs/scoring.md](docs/scoring.md).

- Районы: `esil`, `almaty`, `saryarka`, `baikonur`, `nura`.
- Пять направлений, по два показателя: всего 10 на район.
- Каждый показатель лежит в диапазоне 0–100; больше означает лучше.
- 14 мероприятий с фиксированной ценой, областью действия, лагом и эффектами.
- Бюджет — 100 условных единиц; горизонт — 8 кварталов.
- Персональных данных нет. Датасет используется как контекст и вход расчёта,
  а не для обучения или дообучения моделей.

| Коды | Направление | Показатели |
|---|---|---|
| T1, T2 | Транспорт | Разгрузка дорог; доступность общественного транспорта |
| E1, E2 | Экология | Озеленение; качество воздуха |
| S1, S2 | Социальная инфраструктура | Школы и детсады; первичная медпомощь |
| B1, B2 | Безопасность | Безопасность улиц; безопасность движения |
| C1, C2 | Городские сервисы | Надёжность ЖКХ; скорость решения обращений |

Валидатор требует ровно пять уникальных мероприятий с суммой цен не выше 100
и максимум двумя мероприятиями одной категории. Для районной меры необходим
существующий `district_id`. Для городской меры поле следует полностью исключить
из HTTP-запроса: даже `null` не допускается.

Несовместимости: M1 и M3 запрещены вместе; M4 и M7, а также M5 и M13 запрещены
в одном районе. Бонусы синергий: M1+M2, M10+M12, M5+M6. Порядок решений не влияет
на расчёт. Неиспользованный бюджет не даёт бонуса.

## Расчёт Score

Все числа рассчитываются в Go. Модель AI не участвует в арифметике или валидации.

Для района `d` и показателя `k`:

```text
I_after[d,k] = clip(I_before[d,k]
                   + sum(effect[m,k] * (8 - lag[m]) / 8)
                   + synergy[d,k], 0, 100)

D[d] = sum(weight[k] * I_after[d,k])
D_avg = sum(population_share[d] * D[d])
N_crit = count(I_after[d,k] < 40)

Score = 0.7 * D_avg + 0.3 * min(D[d]) - N_crit
```

В сумму эффектов входят только меры, действующие на данный район. Городская мера
действует на все районы. Синергии добавляются без масштабирования лагом; ограничение
0–100 применяется после суммирования всех эффектов. Порог критического значения
строгий: 40 не считается критическим.

70% веса отражают средний городской результат, 30% — положение слабейшего района.
Каждый критический показатель дополнительно уменьшает оценку на один балл.
Так модель учитывает и общий прогресс, и сохраняющиеся проблемные зоны.
Базовый Score без действий — **52.55768**.

## Архитектура и роль AI

```text
Цель пользователя → POST /api/autopilot → фоновая задача (202)
  → мастер OpenAI: формализовать цель и ограничения
  → планировщик: точный поиск Go → выбор проверенного плана и объяснение OpenAI
  → рецензент OpenAI:
      master  → исправить понимание исходной цели → повторить поиск Go
      planner → исправить предложение или объяснение
      none и approved=true → завершить после проверки Go
  → frontend: показать события, автоматически сохранить и открыть готовый план

HTTP-запрос с решениями
  → httpapi: декодирование и ограничение размера
  → simulation: проверка и детерминированный расчёт
      → /api/simulate: вернуть числа
      → /api/explain: LLM-объяснение либо явно помеченный шаблон
      → /api/advise:
          OpenAI → simulate_scenario → Go-результат → OpenAI
          Go выбирает лучший проверенный вариант
          NVIDIA независимо объясняет риски
```

| Путь | Ответственность |
|---|---|
| [cmd/server](cmd/server) | Настройка и запуск общего HTTP-сервера |
| [internal/simulation](internal/simulation) | Датасет, валидация, расчёт Score и детализации |
| [internal/httpapi](internal/httpapi) | Маршруты, JSON-контракт, ошибки и CORS |
| [internal/explanation](internal/explanation) | Клиенты OpenAI/NVIDIA, резервирование, шаблонное объяснение |
| [internal/advisor](internal/advisor) | Ограниченный агентный цикл, выполнение инструмента, сравнение вариантов |

### Автопилот: исправление цели и подтверждение оптимума

Рецензент возвращает `review.revision_target`: `master`, `planner` или `none`.
При ошибке в формализации мастер получает **тот же исходный запрос пользователя**,
предыдущий `brief` и замечания. Он исправляет перевод в поддерживаемые ограничения,
после чего Go снова ищет допустимые планы. Перед этим прежний результат, объяснение,
рецензия, статистика поиска и подтверждение оптимальности очищаются: план по старой
цели нельзя выдать за ответ на исправленную. Неподдерживаемое или неоднозначное
пожелание приводит к уточнению. Возвраты к обеим ролям расходуют общий лимит итераций.

Для поддерживаемых русских и английских формулировок явного числового бюджета
есть отдельная проверка Go: расхождение с `brief` обнаруживается **до поиска**
и направляется мастеру через событие `explicit_budget_correction`. Ошибка расходует
общую итерацию; начальный вызов мастера входит в первую итерацию. Неоднозначный
или недопустимый распознанный бюджет требует уточнения до вызова API. Это не
универсальный разбор естественного языка: неподдерживаемые формулировки и другие
условия по-прежнему интерпретирует AI.

Необязательный объект `optimality` содержит `proven`, `objective`, `best_value`,
`selected_value`, `gap` и, только для полного поиска по цели `score`, `score_ceiling`.
`proven=true` означает равенство выбранного плана лучшему по текущей формальной цели
**и** итоговому городскому Score. Для `critical_first` меньшее число критических
показателей лучше; для остальных целей большее значение Score лучше.

Для текущего каталога при бюджете 100 максимум городского Score — **57.236735 балла**.
Это баллы модели, **не проценты**. Подтверждение действует только для данного
каталога, формальной цели и ограничений. Оно не доказывает, что LLM верно понял
свободный текст или безошибочно объяснил результат. Поле может появиться до
одобрения рецензента; окончательный статус проверяется отдельно. Контракт и примеры
границ доказательства — в [docs/autopilot.md](docs/autopilot.md).

### OpenAI: предложения и инструмент расчёта

Агент получает каталог, ограничения и исходный результат. Он выбирает аргументы
инструмента `simulate_scenario`: пять мероприятий и районы. Go исполняет расчёт
и возвращает результат или ошибки. Агент может исправить предложение и проверить
ещё один вариант, затем объясняет сравнение.

Максимум — две проверки и три обращения к OpenAI. Выполняется только разрешённый
инструмент расчёта. История `evaluations` содержит публичные проверки и результаты,
а не внутренние рассуждения модели.

Go сравнивает каждую допустимую альтернативу с лучшим уже проверенным результатом.
Замена происходит только при строго большем Score. Если улучшения нет,
`recommended` сохраняет исходный сценарий. Это ограниченный поиск, не гарантия
нахождения глобального оптимума. Рекомендация не применяется автоматически.

### NVIDIA: независимая рецензия и резерв

NVIDIA получает датасет, исходный и выбранный результаты, но не текст OpenAI.
Она объясняет оставшиеся риски, распределение выгод и компромиссы. Это отдельный
взгляд на данные, а не доказательство истинности текста OpenAI.

В обычном `/api/explain` NVIDIA также служит резервом при техническом сбое OpenAI.
Если OpenAI не настроен, NVIDIA может работать основным объясняющим провайдером.

| Доступные ключи | `/api/explain` | `/api/advise` |
|---|---|---|
| Нет | Шаблон, `source=fallback` | Исходный результат, `status=disabled`, без поиска |
| Только OpenAI | OpenAI либо шаблон при сбое | Агент и инструмент; рецензия отключена |
| Только NVIDIA | NVIDIA либо шаблон при сбое | NVIDIA-рецензия исходного результата, поиск отключён |
| Оба | OpenAI → NVIDIA при техническом сбое → шаблон | OpenAI-агент и NVIDIA-рецензент |

Отказ модели не перенаправляется другому провайдеру. Неудача AI не изменяет
рассчитанные числа. Текст может содержать ошибки; числовые карточки нужно строить
по серверным полям результата, а не извлекать числа из текста.

| `HOST_PORT` | `8080` | Внешний порт Docker Compose, не настройка Go-сервера |

`NVIDIA_API_KEY` и `NVIDIA_MODEL` задаются вместе; частичная настройка приводит
к ошибке запуска. Пустые оба значения отключают NVIDIA. Ключи отправляются только
соответствующим провайдерам, не включаются в промпты или ответы API.
`.env` исключён из Git и Docker-контекста. Не публикуйте ключи.

После изменения окружения перезапустите сервер. OpenAI использует Responses API
с `store=false`, NVIDIA — hosted Chat Completions. Конкретные модели и доступность
квот проверяются настоящими вызовами, а не наличием конфигурации.

CORS разрешает точное совпадение `CORS_ORIGIN`, например `http://localhost:5173`.
Пустая строка и `*` не разрешают междоменные запросы. Поддерживаются
GET/POST/OPTIONS и Content-Type, без credentials. CORS не является авторизацией.

## HTTP API

Полный контракт с типами, кодами ошибок и проверяемыми примерами:
[docs/api.md](docs/api.md).

Тела запросов и ответов — JSON. `/simulate`, `/explain`, `/advise` принимают
`{"decisions":[...]}`; `/recommend` — `{"mode":"best"}` или режим улучшения
с решениями; `/autopilot` — `{"goal":"..."}`. Передавать собственные цены,
показатели или Score нельзя.

| Метод и путь | Результат |
|---|---|
| `GET /api/scenario` | Районы, каталог, названия показателей, веса и ограничения |
| `POST /api/simulate` | Валидированный расчёт без обращения к AI |
| `POST /api/explain` | `result` и `explanation:{source,text}` |
| `POST /api/advise` | Исходный результат, лучшая проверенная альтернатива и объяснения |
| `POST /api/recommend` | Лучший план или улучшения существующего плана без вызовов LLM |
| `POST /api/autopilot` | 202, фоновая задача по цели без ручного выбора решений |
| `GET /api/autopilot/{id}` | Состояние, события, результат, рецензия с адресатом исправления, `optimality` и стоимость |
| `POST /api/autopilot/{id}/cancel` | Отмена незавершённой задачи |

### Основные поля расчёта

- `valid`, `total_cost`, `remaining_budget`, отсортированный массив `decisions`.
- `base_score`, `final_score`, `score_delta`, `critical_before`, `critical_after`.
- `district_before_after`: районные показатели и оценки до/после, доли населения.
- `indicator_deltas`: фактические изменения после ограничения диапазоном 0–100.
- `applied_effects`, `applied_synergies`: эффекты до ограничения диапазона и их источники.
- `base_breakdown`, `final_breakdown`: средний результат, минимум и критический штраф.

### Поля ответа советника

| Поле | Смысл |
|---|---|
| `result` | Исходный расчёт пользователя |
| `recommended` | Лучший проверенный расчёт либо исходный |
| `improvement` | `recommended.final_score - result.final_score`, вычислено Go |
| `improved` | Найден ли строго больший Score |
| `evaluations` | До двух проверок: статус и результат/ошибки валидатора |
| `analysis` | `source`, необязательный `provider`, `text`: OpenAI или шаблон |
| `review` | Рецензия NVIDIA либо сообщение о недоступности |
| `status` | Состояние агентного процесса |

Статусы процесса: `complete`, `partial`, `unavailable`, `disabled`, `refused`.
Внутренний вызов с невалидным исходным результатом может вернуть `invalid`;
HTTP-маршрут отклоняет такой запрос раньше. `complete` означает получение финального
текста после инструмента, но не обязательно улучшение. Проверяйте `improved`.

Источники текста: `llm`, `fallback`, `disabled`, `unavailable`.
Подробная семантика — в [AI-интеграции](docs/ai-integration.md).
Отображайте текст обычной интерполяцией, не через `innerHTML`.

### Ошибки и лимиты

| Условие | HTTP / поведение |
|---|---|
| Некорректный JSON, неизвестные поля, несколько объектов | 400 |
| Тело больше 64 КиБ | 413 |
| Нарушение правил симуляции | 422, `valid=false`, `validation_errors`, без Score и AI |
| Два `/api/advise` уже выполняются в данном процессе | 429, `error=advisor_busy`, `Retry-After: 5` |
| AI недоступен при допустимом сценарии | 200 с сохранёнными числами и источником/статусом деградации |

Ошибки 400/413/422 для всех POST-маршрутов имеют одинаковый формат.
Объяснение ограничено 10 секундами; при обоих провайдерах первому выделяется
до 4 секунд. Советник ограничен 45 секундами суммарно: до трёх OpenAI-вызовов
и одной NVIDIA-рецензии, каждый до 10 секунд. Таймаут записи HTTP — 60 секунд.

## Воспроизводимая проверка

### 1. Контрольный расчёт без AI

Сначала запустите сервер. Запрос не требует ключей и не вызывает провайдеров:

```bash
curl -sS http://localhost:8080/api/simulate \
  -H 'Content-Type: application/json' \
  -d '{"decisions":[
    {"measure_id":"M7","district_id":"nura"},
    {"measure_id":"M8","district_id":"nura"},
    {"measure_id":"M10","district_id":"nura"},
    {"measure_id":"M12"},
    {"measure_id":"M5","district_id":"saryarka"}
  ]}'
```

Ожидается HTTP 200 и следующие значения:

| Поле | Значение |
|---|---:|
| `valid` | `true` |
| `total_cost` | 95 |
| `remaining_budget` | 5 |
| `base_score` | 52.55768 |
| `final_score` | 56.54307 |
| `score_delta` | 3.98539 |
| `critical_before` | 2 |
| `critical_after` | 0 |

Для float-полей используйте допуск `1e-9`: JSON содержит неокруглённые `float64`.
В Нуре S1 становится 48, S2 — 43.75. Синергия M10+M12 добавляет B1 +2 сверх
эффекта освещения. Эти значения проверяет `TestGoldenFullIndicatorVectors`.

### 2. Отклонение недопустимого набора

```bash
curl -i http://localhost:8080/api/simulate \
  -H 'Content-Type: application/json' \
  -d '{"decisions":[]}'
```

Ожидается HTTP 422, `valid=false`, ошибка `decision_count`, отсутствие `final_score`.
Замена пути на `/api/explain` или `/api/advise` даёт ту же ошибку без AI-вызовов.
Проверки перерасхода, повторов и несовместимостей входят в `TestValidation`.

### 3. Объяснение и агент

```bash
make demo-explain
make demo-advise
```

Без обоих ключей: объяснение имеет `source=fallback`; советник возвращает
`status=disabled`, `improvement=0`, исходный результат в `recommended`.
С ключами: при успехе объяснение имеет `source=llm`; советник показывает
`evaluations`, `analysis.provider=openai` и, при успешной NVIDIA-рецензии,
`review.provider=nvidia`. Не ожидайте фиксированного текста или гарантированного
улучшения: предложения модели недетерминированы. Числа для одного набора решений
всегда рассчитываются одинаково.

## Тесты и доказательства реализации

```bash
make check   # форматирование, vet, тесты, race detector
make cover   # покрытие пакетов
```

```bash
gofmt -l .

go test ./...
```

В локальной проверке реализации прошли `go test -race -cover ./...` и `go vet ./...`.
Проверка выполнялась Go 1.27.1; в `go.mod` заявлен минимум Go 1.22.
23 сентября 2026 года также проверен `/api/advise` с реальным OpenAI: вызов
инструмента, расчёт альтернативы и финальное объяснение вернулись с `status=complete`.
В одном прогоне проверенное улучшение было предложено; в другом более слабый
вариант был отклонён Go и исходный набор сохранён. NVIDIA и Docker-запуск
пока не подтверждены этой проверкой. В живом тексте обнаружена путаница между
базовым городом и исходным выбором пользователя: в промпт и данные инструмента
добавлено явное сравнение итоговых результатов. Это не гарантирует отсутствие
других ошибок свободного текста. Проверки требуется повторять после изменений.

Три последующих исторических запуска автопилота с OpenAI и проверка браузера
описаны в [docs/autopilot.md](docs/autopilot.md): численный результат во всех трёх
был рассчитан корректно; обнаруженную ошибку в названии действия исправляли
добавлением явных списков мер в контекст. Эти запуски предшествовали новому пути
`reviewer → master → новый поиск` и полю `optimality`.

Отдельная платная проверка с намеренной ошибкой мастера выявила проблему: при
бюджете **95** в исходном запросе мастер был подменён ответом с бюджетом **100**,
а настоящий рецензент в итоге одобрил неверную формализацию. Этот тест **не прошёл**.
Поэтому добавлена проверка явно указанного числового бюджета в Go до поиска.
**Повторный `TestLiveMasterCorrection` прошёл за 31.33 секунды:** Go обнаружил
расхождение через `explicit_budget_correction`, настоящий мастер вернул бюджет 95,
полный поиск и реальные планировщик/рецензент завершили задачу за две итерации.
Получены Score **57.22554500**, расходы города **91**, критических показателей **0**
и `optimality.proven=true`. Три настоящих API-вызова стоили оценочно **$0.007739**;
подменённый начальный ответ мастера не вызывал API. Это проверка восстановления
после **Go-проверки**, не доказательство обнаружения ошибки LLM-рецензентом.

Обычный браузерный запуск текущей версии с новым протоколом и подтверждением
оптимума тоже завершён: Score **57.236735**, бюджет **98/100**, критических
показателей **0**, оценка расходов API около **$0.0079**.

Опциональный `TestLiveMasterCorrection` запускается только с
`RUN_PAID_AUTOPILOT_EVAL=1` и экспортированным API-ключом; обычные тесты его
пропускают. Он вызывает реальные модели после подменённого начального ответа
и использует отдельный лимит $0.10, не включённый в постоянный журнал сервера.
Точная команда, ожидаемые проверки и границы учёта — в [docs/autopilot.md](docs/autopilot.md).

## Ограничения и развитие

- История завершённых планов хранится в браузере. Серверные задания автопилота
  хранятся в памяти до часа; перезапуск сервера их прерывает. Журнал расходов постоянный.
- Правило охвата пяти направлений требует согласования, как указано выше.
- Синтетическая модель не учитывает все причинные связи реального города.
- Прежний `/api/advise` с двумя проверками не гарантирует оптимальный набор.
  Автопилот использует полный поиск по поддерживаемой формализованной цели,
  но AI-перевод пожелания и свободный текст объяснения всё ещё могут ошибаться.
- `encoding/json` допускает разный регистр имён полей и повторяющиеся ключи
  (последнее значение побеждает). Дополнительная проверка этих случаев не реализована.
- Встроенной авторизации и отдельных бюджетов пользователей нет. Журнал бюджета
  автопилота рассчитан на один процесс и не отслеживает `/api/advise`, `/api/explain`
  или другие приложения с тем же API-ключом. Перед публичным размещением нужны
  контроль доступа и общая серверная квота.
- Сравнение команд, карта изменений, случайные события и экспорт презентации
  пока не реализованы. Это направления развития, а не текущие функции.

Практическая ценность прототипа — проверяемое сравнение ограниченного числа
сценариев и понятное объяснение их компромиссов. Для применения к реальному городу
понадобятся проверенные данные, калибровка эффектов и экспертная оценка модели.
