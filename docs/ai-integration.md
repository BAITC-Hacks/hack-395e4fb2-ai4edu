# AI-часть: назначение и интеграция

Наша цель — помочь человеку понять последствия решений и проверить альтернативу.
Датасет описывает условный город. Go моделирует последствия, AI предлагает и
объясняет варианты. Модели не обучаются на датасете: он передаётся как контекст.

## Роли

| Компонент | Работа | Ограничение |
|---|---|---|
| Go `simulation` | Проверяет бюджет, совместимость, направления, считает показатели | Это условная модель, не прогноз реального города |
| OpenAI-советник | Предлагает альтернативы, вызывает расчёт, читает результат | До двух проверок, без обещания глобального оптимума |
| Go `advisor` | Сохраняет исходный сценарий, выбирает лучший проверенный | Принимает только строго больший Score |
| NVIDIA-рецензент | Независимо объясняет риски и компромиссы | Не изменяет числа; текст может ошибаться |
| Шаблонное объяснение | Показывает результат при отсутствии/сбое AI | Помечено `fallback`, не выдаётся за LLM |

## Почему это агент

OpenAI получает инструмент `simulate_scenario` и сам выбирает его аргументы:
пять ID мероприятий и районы. Наш код исполняет только этот инструмент, возвращает
JSON с расчётом или ошибками. Модель может исправить предложение после проверки.
Затем она объясняет результат. Доступа к shell, файлам и реальному бюджету нет.

```text
Пять решений пользователя → Go проверяет и рассчитывает исходный результат
    ↓
OpenAI предлагает вариант → simulate_scenario → Go возвращает результат/ошибки
    ↑                                                    ↓
    └───────── ещё одна проверка при необходимости ───────┘
    ↓
Go выбирает лучший проверенный вариант (или сохраняет исходный)
    ↓
OpenAI объясняет сравнение; NVIDIA независимо разбирает риски
    ↓
Frontend показывает оба варианта и объяснения
```

NVIDIA видит исходные данные и расчёты, а не текст OpenAI: это отдельное мнение.
Рецензия также не является гарантией правильности свободного текста модели.

## Запуск

1. Скопируйте `.env.example` в `.env` в корне репозитория.
2. Задайте `OPENAI_API_KEY` и доступную модель в `OPENAI_MODEL`. При необходимости
   задайте `OPENAI_AGENT_MODEL` с поддержкой Responses API function calling.
3. Для NVIDIA задайте одновременно `NVIDIA_API_KEY` и точный ID `NVIDIA_MODEL`
   из вашего каталога. Совместимость выбранной модели нужно проверить реальным запросом.
4. Запустите `make run` или `docker compose up --build`.
5. `make demo-explain` — объяснение; `make demo-advise` — агент и рецензент.

Ключи остаются на backend и не коммитятся. `make run` и Compose подхватывают `.env`;
при `go run ./cmd/server` экспортируйте переменные самостоятельно.
Реальные вызовы расходуют API-квоту. Тесты используют имитаторы без ключей и сети.

## Контракт frontend

POST `/api/advise` принимает только решения, как `/api/simulate`:

```json
{"decisions":[
  {"measure_id":"M1","district_id":"esil"},
  {"measure_id":"M4","district_id":"saryarka"},
  {"measure_id":"M7","district_id":"nura"},
  {"measure_id":"M10","district_id":"nura"},
  {"measure_id":"M12"}
]}
```

Для городской меры район не указывается. Внутри протокола инструмента OpenAI
используется `district_id:null`; адаптер переводит его в канонический Go-формат.

| Поле ответа | Что показывать |
|---|---|
| `result` | Полный исходный результат симуляции |
| `recommended` | Лучший проверенный результат; может совпадать с исходным |
| `improvement` | Разность итоговых Score, рассчитанная Go |
| `improved` | Найден ли строго больший Score |
| `evaluations` | До двух проверок: статус и результат/ошибки валидатора |
| `analysis` | Объяснение OpenAI или шаблон: `source`, необязательный `provider`, `text` |
| `review` | Рецензия NVIDIA или сообщение о недоступности, тот же формат |
| `status` | Состояние работы советника |

Статусы: `complete` — финальный текст после вызова инструмента; `partial` —
процесс прерван/достиг лимита, проверенные результаты сохранены; `unavailable` —
ошибка до первой проверки; `disabled` — OpenAI не настроен; `refused` — отказ модели;
`invalid` — внутренний вызов с невалидным исходным результатом.
`complete` не означает улучшение: проверяйте `improved`.

Источники текста: `llm`, `fallback`, `disabled`, `unavailable`.
Без NVIDIA `review.source="disabled"`. Без OpenAI NVIDIA может отрецензировать
исходный сценарий, но оптимизация остаётся `disabled`. После отказа OpenAI
рецензент не вызывается. Отмена запроса не запускает новые вызовы.

HTTP 400/413/422 совпадают с `/api/simulate`: AI не вызывается.
Если два `/api/advise` уже выполняются, следующий получает 429 с `Retry-After: 5`.
На frontend выделите около 60 секунд для ответа; серверный лимит процесса — 45 секунд.

Числа показывайте из Go-результатов. Текст — через обычную интерполяцию, не `innerHTML`.
Рекомендованный набор не применяется автоматически: пользователь сам выбирает его.
`evaluations` показывает публичные действия агента, а не скрытые рассуждения модели.

## Резервирование и лимиты

`/api/explain` сохраняет контракт `result` + `explanation:{source,text}`.
При обоих API OpenAI получает до четырёх секунд; при техническом сбое NVIDIA
использует остаток общего десятисекундного срока. После отказа модели резерв
не вызывается. При недоступности обоих используется детерминированное объяснение.
Без OpenAI основным провайдером объяснения становится NVIDIA.

Для `/api/advise` максимум три вызова OpenAI: до двух с инструментом, затем
финальный текст, плюс одна NVIDIA-рецензия. `/api/explain` дополнительно не вызывается.
Отдельный вызов ограничен десятью секундами. Сырые ошибки и ключи не входят в ответ.

## Проверка и ограничения

- Без ключей: числа доступны, источник шаблона помечен.
- С OpenAI: есть `evaluations`, все рекомендации рассчитаны Go.
- С обоими API: при успехе `analysis.provider=openai`, `review.provider=nvidia`.
- Невалидный сценарий: HTTP 422 без AI-вызовов.
- Сбой после расчёта улучшения: числа сохранены, шаблонное объяснение, `partial`.

Автотесты проверяют эти пути с имитаторами. Реальное качество русского текста
и доступность моделей требуют отдельного прогона с ключами. Автотесты не доказывают
отсутствие всех фактических ошибок в тексте модели.

В `scoring.md` и backend сейчас разрешено до двух мер одной категории: возможен
охват трёх направлений. Исходное задание перечисляет пять. Правило нужно согласовать
командой; агент следует текущему валидатору. Синтетические данные не являются
фактическими показателями Астаны.
