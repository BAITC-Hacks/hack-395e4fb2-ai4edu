# «Аким на 5 часов»: готовый показ для жюри

Открыть этот документ рядом с терминалом. Запустить backend в отдельном окне:

```sh
make run OPENAI_API_KEY=
```

Команда включает объяснение через fallback без внешнего AI. Для живого AI
использовать штатную настройку проекта; числа в обоих режимах считает движок.
Все curl ниже готовы к копированию, используют `localhost:8080` и показывают
HTTP-статус через `-i`. JSON-контракт: [api.md](api.md), правила: [scoring.md](scoring.md).

Сервер принимает запросы сразу; `recommend best` до завершения фонового поиска
возвращает **503 not_ready**. В это время показать базу и golden, затем повторить
best. Для готового оптимума ожидается 200. Это состояние готовности, не ошибка
валидации выбранных мер.

## Шпаргалка с числами

Числовые результаты ниже взяты из реальных HTTP-ответов движка.
База — срез **до мер** из ответа golden:
`base_score`, `base_breakdown`, `critical_before`, районные `score_before`.
Нулевая стоимость означает отсутствие действий; нулевая дельта — сравнение
базы с ней самой. Это не успешная симуляция пустого набора: API требует ровно
пять решений. Самый слабый район найден по районным Score и сверяется с
`minimum_district` соответствующего breakdown.

В таблице числа округлены только для показа, до восьми знаков после запятой.
Дельты взяты из `score_delta`, без пересчёта формулы. В выдержках JSON ниже
сохранены исходные float64, включая длинные десятичные хвосты.

| Сценарий | Решения | Стоимость | Score | Δ к базе | Крит. до | Крит. после | Самый слабый район: Score |
|---|---|---:|---:|---:|---:|---:|---|
| База (`base`) | Нет; состояние до мер | 0 | 52.55768000 | 0.00000000 | 2 | 2 | Нура (nura): 49.18000000 |
| Golden (`golden`) | M10→nura; M12→город; M5→saryarka; M7→nura; M8→nura | 95 | 56.54307000 | 3.98539000 | 2 | 0 | Нура (nura): 52.96250000 |
| Оптимум (`optimal`) | M14→город; M2→город; M3→nura; M8→nura; M9→nura | 98 | 57.23673500 | 4.67905500 | 2 | 0 | Нура (nura): 54.09125000 |
| Перекос (`skew`) | M1→esil; M10→esil; M13→esil; M4→esil; M8→esil | 93 | 53.57686250 | 1.01918250 | 2 | 2 | Нура (nura): 49.18000000 |
| Ловушка (`trap`) | M11→almaty; M12→город; M5→saryarka; M7→nura; M8→nura | 93 | 55.14404000 | 2.58636000 | 2 | 1 | Нура (nura): 51.68000000 |

`nura` — Нура, `esil` — Есиль, `almaty` — Алматы, `saryarka` — Сарыарка.
«Город» означает, что `district_id` отсутствует. Решения в таблице расположены
в каноническом порядке ответа движка; входной порядок на результат не влияет.
Стоимость — условные единицы; Score и дельта — баллы. Критическое значение —
пара «район × показатель», а не целый район.

## База: начать с того, что городу уже нужно исправить

Сказать: «До наших решений в Нуре есть два критических показателя — школы
и первичная медицина. Это исходная точка, с которой сравниваются все наборы».

Команда отправляет валидный golden-набор, но здесь показываем только поля
**до** применения мер. В ответе найти `base_score`, `base_breakdown` и
`critical_before`; не путать их с `final_score` того же ответа.

<!-- demo:base-curl -->
```sh
curl -sS -i http://localhost:8080/api/simulate \
  -H 'Content-Type: application/json' \
  --data-raw '{"decisions":[{"measure_id":"M7","district_id":"nura"},{"measure_id":"M8","district_id":"nura"},{"measure_id":"M10","district_id":"nura"},{"measure_id":"M12"},{"measure_id":"M5","district_id":"saryarka"}]}'
```

Выдержка из ответа 200 (поля до мер):

<!-- example:demo-base-response -->
```json
{
  "base_score": 52.557680000000005,
  "critical_before": 2,
  "base_breakdown": {
    "weighted_average": 56.8624,
    "minimum_district": 49.18000000000001,
    "critical_penalty": 2
  }
}
```

## Golden: сбалансированное решение

Сказать: «Строим школу и поликлинику в Нуре, добавляем освещение и цифровую
платформу; в Сарыарке переводим частный сектор на чистое топливо. Синергия
освещения и платформы тоже учитывается движком. Оба исходных критических
показателя устранены».

<!-- demo:golden-curl -->
```sh
curl -sS -i http://localhost:8080/api/simulate \
  -H 'Content-Type: application/json' \
  --data-raw '{"decisions":[{"measure_id":"M7","district_id":"nura"},{"measure_id":"M8","district_id":"nura"},{"measure_id":"M10","district_id":"nura"},{"measure_id":"M12"},{"measure_id":"M5","district_id":"saryarka"}]}'
```

Выдержка из ответа 200:

<!-- example:demo-golden-response -->
```json
{
  "total_cost": 95,
  "final_score": 56.54306999999999,
  "score_delta": 3.985389999999988,
  "critical_before": 2,
  "critical_after": 0,
  "final_breakdown": {
    "weighted_average": 58.07759999999999,
    "minimum_district": 52.962500000000006,
    "critical_penalty": 0
  }
}
```

Чтобы показать объяснение, выполнить тот же запрос, заменив путь
`/api/simulate` на `/api/explain`. Сначала обратить внимание на `result`,
затем прочитать `explanation.text`. При `source=fallback` честно назвать
это шаблонным объяснением; при `source=llm` — объяснением AI. При включении
или отключении AI менять решения и формулу не требуется.

## Оптимум: сравнить ручной набор с точным поиском

Сказать: «Для нашей конечной модели можем не гадать: проверяем все допустимые
варианты через тот же движок и выбираем лучший. Это оптимум данной модели,
а не обещание оптимальности реальной городской политики».

## «Перекос»: вложить весь бюджет выбранных мер в Есиль

Все пять мер районные и направлены в Есиль: автобусные полосы, парк,
поликлиника, освещение и модернизация сетей. Набор валиден; городской меры нет.

<!-- demo:skew-curl -->
```sh
curl -sS -i http://localhost:8080/api/simulate \
  -H 'Content-Type: application/json' \
  --data-raw '{"decisions":[{"measure_id":"M1","district_id":"esil"},{"measure_id":"M4","district_id":"esil"},{"measure_id":"M8","district_id":"esil"},{"measure_id":"M10","district_id":"esil"},{"measure_id":"M13","district_id":"esil"}]}'
```

Сказать: «Тратим 93, и районный Score Есиля растёт с 62.99000000
до 68.38250000. Но самый слабый район не улучшился, и исходные
критические показатели остались. Поэтому общий прирост только 1.01918250».

Важное сравнение с golden: средневзвешенный районный Score здесь даже выше
(58.31837500 против 58.07760000),
а итоговый городской Score ниже. Влияют и вес слабейшего района
(0.3), и штрафы; не приписывать весь разрыв только одному слагаемому.

Выдержка из ответа 200:

<!-- example:demo-skew-response -->
```json
{
  "total_cost": 93,
  "final_score": 53.57686249999999,
  "score_delta": 1.0191824999999852,
  "critical_before": 2,
  "critical_after": 2,
  "final_breakdown": {
    "weighted_average": 58.318374999999996,
    "minimum_district": 49.18000000000001,
    "critical_penalty": 2
  }
}
```

## «Ловушка»: полезная мера может создать новый критический провал

Берём школу и поликлинику в Нуре, городскую цифровую платформу, чистое топливо
в Сарыарке, а вместо освещения — безопасные переходы M11 в Алматы.

<!-- demo:trap-curl -->
```sh
curl -sS -i http://localhost:8080/api/simulate \
  -H 'Content-Type: application/json' \
  --data-raw '{"decisions":[{"measure_id":"M7","district_id":"nura"},{"measure_id":"M8","district_id":"nura"},{"measure_id":"M11","district_id":"almaty"},{"measure_id":"M12"},{"measure_id":"M5","district_id":"saryarka"}]}'
```

Фактические изменения в Алматы из `district_before_after` и `indicator_deltas`:

| Показатель Алматы | До | После | Δ |
|---|---:|---:|---:|
| T1 | 40.00000000 | 38.25000000 | -1.75000000 |
| B2 | 52.00000000 | 62.50000000 | 10.50000000 |

Сказать: «Дорожная безопасность улучшается, но T1 опускается ниже критического
порога 40. Получаем новый штраф в 1
балл. Нельзя выбирать меры только по положительным эффектам».

Уточнить: число критических значений меняется с 2 на 1, а не растёт
суммарно. Школа и поликлиника закрыли оба старых провала в Нуре; новый,
оставшийся после сценария, — именно T1 в Алматы. Это видно по отдельным
показателям и `final_breakdown.critical_penalty`.

Выдержка из ответа 200:

<!-- example:demo-trap-response -->
```json
{
  "total_cost": 93,
  "final_score": 55.14403999999999,
  "score_delta": 2.586359999999985,
  "critical_before": 2,
  "critical_after": 1,
  "final_breakdown": {
    "weighted_average": 58.057199999999995,
    "minimum_district": 51.68000000000001,
    "critical_penalty": 1
  }
}
```

## Что сказать жюри

- «Все числа считает детерминированный Go-движок. При одинаковых решениях
  получаем одинаковый JSON; доступность AI не влияет на Score».
- «AI объясняет уже вычисленный результат: сильные стороны, риски и
  компромиссы. Он не назначает оценки и не меняет правила».
- «Вес 0.3 × min районных Score не даёт забыть Нуру. Пример с Есилем показывает,
  что красивый средний показатель ещё не означает хорошее решение для города».
- «Критические показатели имеют отдельный штраф. В примере с M11 виден риск:
  улучшение безопасности одновременно создаёт новый провал по T1».
- «`/api/recommend` находит точный оптимум полным перебором 694 395 допустимых
  сценариев. Их число закреплено тестом оптимизатора; каждую оценку даёт
  `simulation.Simulate`, без второй реализации формулы».
- «Предложения AI проверяются движком: предлагаемый набор решений отправляем
  в `/api/simulate`. Только валидный набор получает Score; ответ 422 означает,
  что предложение надо исправить. Это тот же контроль, что для решений человека».
- «Мы показываем последствия внутри прозрачной модели. Можно обсуждать её
  веса, данные и ограничения; объяснение AI не заменяет проверку этих допущений».

## Проверка актуальности перед выступлением

```sh
go test ./internal/httpapi -run TestDemoScenarios -count=1
```

Тест читает curl-запросы и таблицу прямо из этого документа, выполняет их через
реальный handler и сверяет стоимость, Score, дельту, критические значения и
слабейший район. Он также проверяет JSON-выдержки, ответ 422 без Score,
результат best и новую критическую пару в «ловушке». Для best используется
общий кэш оптимизатора: полный расчёт не повторяется для каждого примера.
При изменении движка заново снять HTTP-ответы и обновить документ;
не подгонять числа вручную.
